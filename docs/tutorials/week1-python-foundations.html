0 Before you start

A few minutes here saves an hour later. Most early frustration is not Python — it is the terminal.

Check that you have Python 3

Open a terminal and run:

python3 --version

You should see something like Python 3.11.4. Any version starting with 3 is fine. If the command is not found, install Python from python.org first.

Two ways to run Python

Typing python3 on its own opens the REPL — an interactive prompt where each line runs as soon as you press Enter. It is perfect for trying one small thing. Type exit() to leave.

Everything you hand in is a script instead: a file ending in .py that you run in one go. 

python3 hello.py

Your terminal is standing somewhere

When you run python3 hello.py, the terminal looks for hello.py in the folder it is currently standing in. pwd tells you where that is, ls lists what is there, and cd moves you. If Python says it cannot find your file, you are almost always in the wrong folder.

A virtual environment

Later projects install packages such as pandas. A virtual environment keeps those installs inside your project instead of spreading them across your computer. Create and activate one now: 

python3 -m venv venv
source venv/bin/activate     # macOS / Linux
venv\Scripts\activate        # Windows

Your prompt now starts with (venv). Run deactivate when you are done for the day.

Try it · your first script

Two minutes, and you have confirmed your whole setup works.

  • Create a folder called warmup and cd into it.
  • Create a file hello.py containing one line: print("Ready for week 1").
  • Run it with python3 hello.py.
  • Now cd .. and run it again. Read the error you get, then fix it by pointing at warmup/hello.py.

1 Values and types

Every value in Python has a type, and the type decides what the value can do.

The four you need this week

  • int – a whole number: 10
  • float – a decimal number: 1.20
  • str – text, always in quotes: "Pen"
  • bool – True or False

A variable is just a name pointing at a value. You do not declare its type; Python works it out. type() tells you what you actually have: 

quantity = 10
price = 1.20
product = "Pen"

print(type(quantity))   # <class 'int'>
print(type(price))      # <class 'float'>
print(type(product))    # <class 'str'>

The one sentence to remember

Everything you read from a file is a string. Even when it looks like a number. This is the single most common cause of wrong answers in Project 1: 

quantity = "10"          # straight from a file
print(quantity * 3)      # 101010  ← repeated the text three times

quantity = int("10")     # converted to a number
print(quantity * 3)      # 30      ← that is more like it

Convert with int(), float() and str(). If the text is not a valid number, int("abc") raises an error — which is exactly the situation Task 2 asks you to handle.

Why you need it: Task 1 sums quantity and quantity * price. Without int() and float(), neither total is a number.

Try it · predict, then check

Guess the output before you run each line in the REPL.

  • print("3" + "4")
  • print(3 + 4)
  • print(int("3") + int("4"))
  • print(float("2.5") * 4)
  • print(type(2.5 * 4)) — is the result an int or a float?

Any line where your guess was wrong is worth two minutes of your attention.

2 Strings

Your data arrives as text, so text handling is most of the work in Project 1.

Building output with f-strings

Put an f before the quotes and you can drop variables straight into the text using curly braces. This is how you print readable summaries: 

customer = "Alice"
total = 38.99

print(f"{customer} spent {total} in total")
print(f"{customer} spent {total:.2f} in total")   # two decimal places

Three methods that do most of the work

A line read from a file looks like this, invisible newline included:

line = "124|Bob|Pen|10|1.20\n"

.strip() removes whitespace and that trailing newline from both ends:

clean = line.strip()        # "124|Bob|Pen|10|1.20"

.split("|") cuts the text wherever it finds a pipe and hands you back a list of pieces:

fields = clean.split("|")
print(fields)               # ['124', 'Bob', 'Pen', '10', '1.20']

.lower() makes comparison reliable, since "Pen" and "pen" are not equal:

print("Pen".lower() == "pen")   # True

Length, indexing, slicing

product = "Notebook"

print(len(product))     # 8
print(product[0])       # N        ← counting starts at 0
print(product[-1])      # k        ← negative counts from the end
print(product[0:4])     # Note     ← from 0 up to, not including, 4

Why you need it: Tasks 0 and 1 both live on .strip() followed by .split("|"). Every printed summary is an f-string.

Try it · take a line apart

One line of raw data, five clean fields.

  • Start from row = " 201|Ana|Lamp|3|12.50 \n".
  • Strip it, split it on "|", and print the resulting list.
  • Print just the product name, using its position in the list.
  • Print a sentence with an f-string: Ana ordered 3 Lamp.
  • What happens if you split before you strip? Look closely at the last item.

3 Lists

An ordered collection of values. .split() gives you one, so you already have them.

Creating and reaching into a list

fields = ["124", "Bob", "Pen", "10", "1.20"]

print(len(fields))      # 5
print(fields[1])        # Bob
print(fields[-1])       # 1.20

fields.append("extra")  # add to the end

Unpacking

When you know exactly how many pieces there are, give them all names at once. This is far easier to read than fields[0], fields[1], fields[2] scattered through your code: 

order_id, customer, product, quantity, price = fields

print(customer)     # Bob

Unpacking fails loudly if the line has the wrong number of fields — which is useful, because a malformed row is something you want to notice rather than silently miscount.

Tuples, in one line

A tuple is a list you cannot change, written with round brackets: (3, 12.50). You will meet them returned from functions. That is all you need for now.

Dictionaries — the other big one — are the subject of Project 2. The stretch task at the end of Project 1 gives you an early taste, and that is deliberate.

Try it · name your fields

Turn positions into names.

  • Split "201|Ana|Lamp|3|12.50" and unpack it into five named variables.
  • Convert quantity to an int and price to a float.
  • Print the line total using an f-string, formatted to two decimals.
  • Now try unpacking a line with only four fields. Read the error message carefully.

4 Making decisions and repeating work

Conditions choose between paths. Loops repeat a path once per item.

Conditions

Python groups code by indentation. Everything indented under an if belongs to it — there are no braces, so the spacing is the structure: 

quantity = 10

if quantity > 5:
    print("bulk order")
elif quantity == 5:
    print("exactly five")
else:
    print("small order")

Compare with ==, !=, <, >, <=, >=. Note that = assigns a value while == asks a question. Combine conditions with and, or and not: 

if quantity > 0 and price > 0:
    print("valid row")

Loops

A for loop runs its body once for each item:

products = ["Notebook", "Pen", "Backpack"]

for product in products:
    print(product)

range(3) gives you 0, 1, 2 when you need a count rather than a collection. More usefully for Project 1, enumerate() gives you the position and the item together: 

for index, product in enumerate(products):
    print(index, product)

# 0 Notebook
# 1 Pen
# 2 Backpack

That index is how you tell the header row apart from the data rows: row 0 is the header, everything after it is data.

Accumulating a total

Start a counter at zero outside the loop, add to it inside. This pattern is the whole of Task 1: 

total = 0

for quantity in [2, 10, 1]:
    total = total + quantity      # or: total += quantity

print(total)    # 13

break leaves the loop early; continue skips to the next item. continue is how you skip a bad row without abandoning the file.

Why you need it: Task 0 uses enumerate() to find the header and the first three data rows. Task 1 is a loop with counters.

Try it · count and total

The core loop of Project 1, on a list instead of a file.

  • Make a list of five rows as strings, each like "201|Ana|Lamp|3|12.50".
  • Loop over it and keep two counters: how many rows, and total quantity.
  • Add a third counter for revenue: quantity times price, summed.
  • Use enumerate() to skip the first row as if it were a header.

5 Functions

A named piece of work you can run again. Functions are what make Task 3 possible instead of painful.

Defining and calling

def line_total(quantity, price):
    """Return the total value of one order line."""
    return quantity * price


print(line_total(10, 1.20))     # 12.0

The values in the brackets are parameters going in; return sends one value back out. The text in triple quotes is a docstring — one sentence saying what the function does.

Default values

Give a parameter a default and callers can leave it out:

def parse_row(line, separator="|"):
    return line.strip().split(separator)


parse_row("124|Bob|Pen")            # uses "|"
parse_row("124,Bob,Pen", ",")       # uses ","

Return, do not print

This distinction matters more than it looks. A function that prints has done its work and thrown the result away. A function that returns hands the result to the caller, who can print it, add it up, or pass it somewhere else: 

def total_revenue(rows):        # returns — reusable
    return sum(rows)

def show_revenue(rows):         # prints — a dead end
    print(sum(rows))

Keep calculation and printing separate. Calculate in one function, print in another.

Scope

A variable created inside a function only exists inside it. That is a feature: it means two functions cannot quietly interfere with each other. Anything a function needs should come in as a parameter.

Why you need it: Task 1 suggests parse_order_line(line), and Task 3 requires toolbox.py to reuse your earlier functions rather than duplicate them. That only works if they return values.

Try it · one job each

Split your loop into small named pieces.

  • Write parse_row(line) that strips, splits, and returns the list of fields.
  • Write row_total(fields) that converts and returns quantity times price.
  • Write summarise(rows) that returns the count and the revenue.
  • Print the summary from outside the functions, not inside them.

6 Modules and the main() pattern

Every .py file is a module. Files can borrow code from each other.

Importing

The standard library comes with Python — nothing to install:

import sys
import os

print(sys.argv)
print(os.path.exists("data/sample_orders.txt"))

Or bring in just the piece you want:

from os.path import exists

print(exists("data/sample_orders.txt"))

Importing your own files

If toolbox.py sits next to order_stats.py, it can use its functions by name: 

from order_stats import parse_order_line

fields = parse_order_line("124|Bob|Pen|10|1.20")

What if __name__ == "__main__": actually does

Here is the problem it solves. When you import a file, Python runs that file top to bottom to find out what is in it. Any loose code at the bottom therefore executes during the import — which you almost never want.

Python sets a variable __name__ in every module. It equals "__main__" when the file is the one you launched, and the module's own name when it was imported. So this line means: run the following only when I am the script, not when someone imports me. 

def main():
    print("doing the real work")


if __name__ == "__main__":
    main()

Why you need it: Task 3 imports your scripts from toolbox.py. Without this guard, importing them would run them.

Try it · see the guard work

Prove to yourself what the guard prevents.

  • Create helper.py with a function and, at the bottom, a bare print("helper is running").
  • Create runner.py that imports the function from helper.
  • Run python3 runner.py. Notice the helper's print appears anyway.
  • Wrap the print in a main() plus the guard, and run it again.

7 Reading files

The bridge between everything above and the actual data in Project 1.

Open it the safe way

open() gives you a file object; with guarantees it gets closed again, even if something fails partway through. Always use with: 

with open("data/sample_orders.txt") as f:
    contents = f.read()

print(contents)

The default mode is read. You will also see "w" for write and "a" for append, but Project 1 only reads.

Line by line

Reading the whole file at once is fine for small files; looping is the habit to build:

with open("data/sample_orders.txt") as f:
    for line in f:
        print(line.strip())

Every line still carries its \n at the end, which is why .strip() appears in almost every example. Forget it and your last field ends up as "1.20\n", which float() handles but comparisons do not.

Header plus data, together at last

with open("data/sample_orders.txt") as f:
    for index, line in enumerate(f):
        if index == 0:
            print("header:", line.strip())
            continue

        fields = line.strip().split("|")
        print(fields)

Where is the file?

"data/sample_orders.txt" is a relative path — relative to wherever you ran the command, not to where the script lives. Running from your repo root and from inside project01/ will give different results. Pick one and be consistent; the project pages assume you run from the repo root.

Why you need it: this is Task 0 in full, and the first half of Task 1.

Try it · read a real file

  • Print the header, then the number of data rows.
  • Print the total number of pages across all books.
  • Print the title of the longest book.

8 When things go wrong

Errors are information, not failure. Learning to read them is a real skill.

Read the traceback from the bottom

The last line names the error type and describes the problem. The lines above it show how Python got there, most recent last. Start at the bottom and work up only if you need to: 

Traceback (most recent call last):
  File "order_stats.py", line 12, in <module>
    quantity = int(fields[3])
ValueError: invalid literal for int() with base 10: 'ten'

That message tells you exactly what happened: something said ten where a number belonged.

The four you will meet this week

  • FileNotFoundError – wrong path, or wrong folder.
  • ValueError – int() or float() got text it cannot convert.
  • IndexError – you asked for fields[4] and the row only had four fields.
  • TypeError – you tried to do arithmetic on a string you forgot to convert.

Handling instead of crashing

try runs the risky code; except catches one specific type of failure and decides what to do about it. Catch the specific error, not everything: 

invalid = 0

for line in lines:
    fields = line.strip().split("|")
    try:
        quantity = int(fields[3])
        price = float(fields[4])
    except (ValueError, IndexError):
        invalid += 1
        continue

    total += quantity * price

The row is counted as invalid, skipped, and the file keeps going. That is exactly what Task 2 asks for.

Failing on purpose

Some problems are not recoverable. If the file does not exist, say so clearly and stop with a non-zero exit code, which is how command-line tools signal failure: 

import sys

try:
    with open(path) as f:
        ...
except FileNotFoundError:
    print(f"Error: could not open {path}")
    sys.exit(1)

Why you need it: Task 0 requires a clear message and a non-zero exit. Task 2 requires counting invalid rows without crashing.

Try it · break it deliberately

Cause each error, then handle it.

  • Point your script at a filename that does not exist. Read the traceback.
  • Add a row to books.txt where pages says many.
  • Add a row missing its last field entirely.
  • Handle both bad rows, count them, and print Processed 4 rows, skipped 2 invalid.

9 Command-line arguments

Stop editing your script to change which file it reads. Tell it from outside.

The simple way: sys.argv

sys.argv is a plain list of what you typed. Position 0 is the script name; everything after is an argument: 

import sys

print(sys.argv)

# $ python3 info.py data/sample_orders.txt
# ['info.py', 'data/sample_orders.txt']
if len(sys.argv) < 2:
    print("Usage: python3 info.py PATH")
    sys.exit(1)

path = sys.argv[1]

Notice the length check. Reaching for sys.argv[1] when nothing was typed is an IndexError.

The grown-up way: argparse

argparse handles named options, defaults, type conversion and a generated --help screen for you: 

import argparse

parser = argparse.ArgumentParser(description="Summarise an orders file")
parser.add_argument("--file", default="data/sample_orders.txt")
parser.add_argument("--limit", type=int, default=None)

args = parser.parse_args()

print(args.file)
print(args.limit)
python3 order_stats.py
python3 order_stats.py --file data/other.txt --limit 5
python3 order_stats.py --help

default= means the script runs with no arguments at all. type=int means args.limit arrives as a number, already converted.

Subcommands, briefly

Task 3 wants toolbox.py info ... and toolbox.py stats .... You can do this by checking sys.argv[1] against the word "info" or "stats" and calling the matching function — that is enough. If you want the polished version, look up parser.add_subparsers().

Why you need it: Task 0 takes a path argument, Task 2 adds --file and --limit, Task 3 routes subcommands.

Try it · make your reader configurable

Same script, different inputs, no editing.

  • Take your books script and accept the path via sys.argv.
  • Handle the case where no path is given: usage message, exit code 1.
  • Rewrite it with argparse, defaulting to books.txt.
  • Add --limit and stop after that many data rows.
  • Run --help and read what argparse built for you.

10 Putting it together

One script using every idea above. It is the shape of Project 1, on different data — so read it as a pattern, not an answer to copy.

The data: books.txt

title|author|pages
The Hobbit|Tolkien|310
Dune|Herbert|412
Sula|Morrison|174
Broken Glass|Unknown|many

The script: book_stats.py

import argparse
import sys


def parse_book_line(line):
    """Turn one raw line into (title, author, pages)."""
    title, author, pages = line.strip().split("|")
    return title, author, int(pages)


def summarise(path):
    """Return counts and totals for the file at path."""
    books = 0
    invalid = 0
    total_pages = 0

    with open(path) as f:
        for index, line in enumerate(f):
            if index == 0:
                continue

            try:
                title, author, pages = parse_book_line(line)
            except ValueError:
                invalid += 1
                continue

            books += 1
            total_pages += pages

    return books, invalid, total_pages


def main():
    parser = argparse.ArgumentParser(description="Summarise a books file")
    parser.add_argument("--file", default="books.txt")
    args = parser.parse_args()

    try:
        books, invalid, total_pages = summarise(args.file)
    except FileNotFoundError:
        print(f"Error: could not open {args.file}")
        sys.exit(1)

    print(f"Books read:   {books}")
    print(f"Invalid rows: {invalid}")
    print(f"Total pages:  {total_pages}")


if __name__ == "__main__":
    main()

What to notice

  • parse_book_line does one job and returns a value. Nothing prints inside it.
  • summarise returns three numbers. It does not know or care that they will be printed.
  • main is the only place that talks to the user.
  • The bad row is caught, counted, and skipped — the file still finishes.
  • Both the unpacking failure and the int() failure raise ValueError, so one except covers both.

That separation is why Task 3 is easy: toolbox.py can import summarise and use it without inheriting any printing.
