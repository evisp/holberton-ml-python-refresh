Project 2

Data structures – working with JSON records

In this project you load a realistic JSON dataset of todo items and practice working with lists, dictionaries, and sets to query, group, and analyze the data in memory.

Learning goals

  • Load JSON data into native Python structures (lists and dictionaries).
  • Practice filtering, mapping, and aggregating records using lists and dicts.
  • Build simple in-memory indices to support faster and clearer queries.
  • Use sets to reason about uniqueness and membership (which users have which todos).

Project context

You continue working inside the same personal repository you used for Project 1. Each project lives in its own folder (project01/, project02/, …), so you gradually build a coherent codebase.

In this project you work with a fake but realistic JSON dataset of todo items from JSONPlaceholder, a free REST API for testing and prototyping. You will download the data once, save it locally, and then focus on in-memory operations.

Download the todos dataset

You will use one shared JSON file containing todo records. Everyone works from the same source.

JSONPlaceholder todos

The dataset comes from JSONPlaceholder, a public fake REST API used for testing and prototyping. You will download the /todos resource and save it as a JSON file in your repository.

API endpoint: 

https://jsonplaceholder.typicode.com/todos

Option 1 · Download with curl (recommended)

From the root of your personal repository, run:

mkdir -p project02/data
curl https://jsonplaceholder.typicode.com/todos -o project02/data/todos.json

Option 2 · Download with a short Python script

Create a temporary script (for example download_todos.py at the repo root) and run it once:

import json
import urllib.request

url = "https://jsonplaceholder.typicode.com/todos"
response = urllib.request.urlopen(url)
data = json.loads(response.read().decode("utf-8"))

# Ensure the project02/data folder exists
import os
os.makedirs("project02/data", exist_ok=True)

with open("project02/data/todos.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

After running one of these options, you should have a local file: 

project02/data/todos.json

Task 0 · load and inspect JSON

Bridge your file-handling skills from Project 1 into JSON and native Python structures.

Requirements

  • Create scripts/load_data.py inside project02/.
  • Use the json module to load data/todos.json into a Python object.
  • Print:
    • The type of the top-level object (should be a list).
    • The total number of records.
    • The keys present in a typical record (for example from the first item).

Hints

  • Reuse the pattern from Project 1: open the file, then parse it.
  • Check type(data) after loading, and inspect data[0] to see its fields.
  • Keep the loading logic in a function (for example load_todos(path)) so you can reuse it later.

Task 1 · basic queries with lists and dicts

Practice filtering and aggregating records using lists and dictionaries.

Requirements

  • Create scripts/queries.py.
  • Import your loading function from load_data.py and work with the in-memory list of todos.
  • Implement functions such as:
    • get_todos_by_user(todos, user_id) – returns a list of todo items for a given userId.
    • count_completed_by_user(todos) – returns a dictionary mapping userId to the number of completed todos.
    • get_users_with_all_completed(todos) – returns a list or set of userId values where all todos are completed.

Suggested progression

  • 1.1 – Start with a simple filter: todos for one user.
  • 1.2 – Build a dictionary of counts per user.
  • 1.3 – Derive the set of users whose todos are all completed using your previous results.

Hints

  • Use list comprehensions to filter records by userId or by completed status.
  • For counts, think in terms of “dictionary with userId as key and count as value”.
  • Reuse your functions later; avoid mixing printing and logic in the same function.

Task 2 · building in-memory indices

Build small indices (maps) that make your queries clearer and more efficient.

Requirements

  • Create scripts/indexing.py.
  • Implement functions such as:
    • build_user_index(todos) – returns a dict mapping userId to a list of todos.
    • build_completion_index(todos) – returns a dict with keys like "completed" and "pending" mapping to lists of todos.
  • Use these indices from queries.py to answer some questions more elegantly.

Suggested progression

  • 2.1 – Build the user index and use it to re-implement get_todos_by_user.
  • 2.2 – Build the completion index and use it to quickly get all completed or pending todos.
  • 2.3 – Compare your code with and without indices (even just in terms of clarity).

Hints

  • Think of indices as “precomputed groupings” that you can reuse instead of scanning the full list every time.
  • Even if performance differences are small on this dataset, the pattern matters for larger data in ML contexts.

Task 3 · sets and uniqueness

Use sets to reason about uniqueness and relationships between users and their todos.

Requirements

  • Create scripts/sets_playground.py.
  • Load todos.json (either directly or via your existing loading function).
  • Perform operations such as:
    • Compute the set of all userId values.
    • Compute the set of users who have at least one pending todo.
    • Compute the set of users whose todos are all completed.
    • Use set operations (union, intersection, difference) to compare these sets.

Suggested progression

  • 3.1 – Start with a simple set of all userId values.
  • 3.2 – Derive users_with_pending and users_with_completed_only.
  • 3.3 – Use set difference and intersection to answer questions like “Who still has work to do?”

Hints

  • Sets are great when you care about membership and uniqueness rather than the exact order.
  • Relate this to ML scenarios where you might track unique labels, unique users, or intersections of conditions.

Optional · small query shell

Integrate your functions into a simple text-based “query shell” so you can explore the data interactively.

Optional requirements

Hints

  • Keep the shell simple; focus on reusing your existing logic rather than building a full CLI tool.
  • This mirrors the “toolbox” idea from Project 1, but now you are working with JSON records.

Stretch goals (optional)

Extra challenges if you want to push your data-structure skills further.

Optional extensions

  • Implement a simple keyword search on todo titles, returning matching records for a given word.
