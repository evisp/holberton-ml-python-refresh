Project 2

Data structures – working with JSON records

In this project you move from plain text and pipes to JSON records. You will load a realistic todos dataset, then practice using lists, dictionaries, and sets to filter, group, and build small indices in memory.

📄 JSON records 📋 Lists & loops 🔑 Dicts & indices 🧩 Sets & membership
Focus: lists, dicts, sets Data: JSONPlaceholder todos Goal: think in records before pandas

Key concepts

  • Loading JSON into native Python structures (lists and dicts).
  • Filtering and aggregating records with loops and list comprehensions.
  • Building simple indices (maps) keyed by userId or status.
  • Using sets to represent unique users and relationships.

Study first (15–30 minutes)

  • New to dictionaries and sets? Work through the Week 2 JSON records tutorial first — it covers everything below, using this same dataset.
  • Python docs: built-in types (lists, dicts, sets).
  • Python docs: json module for loading and dumping JSON.
  • Quick recap of list comprehensions and collections.Counter.
  • Skim JSONPlaceholder’s description of the /todos resource.

Knowing how lists and dicts behave will make the tasks feel much more natural.

Download the todos dataset

You will use one shared JSON file containing todo records. Everyone works from the same source.

JSONPlaceholder todos

The dataset comes from JSONPlaceholder, a public fake REST API used for testing and prototyping. You will download the /todos resource and save it as a JSON file in your repository.

API endpoint:

https://jsonplaceholder.typicode.com/todos

Option 1 · Download with curl (recommended)

From the root of your personal repository, run:

mkdir -p project02/data
curl https://jsonplaceholder.typicode.com/todos -o project02/data/todos.json

Option 2 · Download with a short Python script

Create a temporary script (for example download_todos.py at the repo root) and run it once:

import json
import urllib.request
import os

url = "https://jsonplaceholder.typicode.com/todos"
response = urllib.request.urlopen(url)
data = json.loads(response.read().decode("utf-8"))

os.makedirs("project02/data", exist_ok=True)
with open("project02/data/todos.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

After running one of these options, you should have a local file: 

project02/data/todos.json

Tasks

Load the JSON once, then build up from inspection to queries, indices, and sets. The cards expand with details as you progress.

Task 0 · load and inspect JSON

Bridge your file-handling skills from Project 1 into JSON and native Python structures.

Requirements

  • Create scripts/load_data.py inside project02/.
  • Implement a function load_todos(path) that:
    • Opens todos.json.
    • Parses it with json.load.
    • Returns the parsed Python object.
  • In a main() block, print:
    • The type of the top-level object (should be list).
    • The total number of records.
    • The keys present in the first item.

Hints

  • Check type(data) after loading, and inspect data[0] to see its fields.
  • Keep the loading logic in a reusable function so other scripts can call it.

Task 1 · basic queries with lists and dicts

Filter and aggregate todos by user and completion status using lists and dictionaries.

Requirements

  • Create scripts/queries.py.
  • Import load_todos from load_data.py and work with the in-memory list.
  • Implement functions such as:
    • get_todos_by_user(todos, user_id) – returns a list of todo items for a given userId.
    • count_completed_by_user(todos) – returns a dictionary mapping userId to the number of completed todos.
    • get_users_with_all_completed(todos) – returns a list or set of userId values whose todos are all completed.

Suggested progression

  • 1.1 – Start with a simple filter: todos for one user.
  • 1.2 – Build a dictionary of counts per user.
  • 1.3 – Derive the set of users whose todos are all completed using your previous results.

Hints

  • Use list comprehensions to filter by userId or by completed status.
  • For counts, think in terms of “dict where key is userId and value is a count”.
  • Keep logic separate from printing; it will be easier to reuse and test.

Task 2 · building in-memory indices

Build small indices (maps) that make your queries clearer and more efficient.

Requirements

  • Create scripts/indexing.py.
  • Implement functions such as:
    • build_user_index(todos) – returns a dict mapping userId to a list of todos.
    • build_completion_index(todos) – returns a dict with keys like "completed" and "pending" mapping to lists of todos.
  • Use these indices from queries.py to re-implement or simplify some of your earlier functions.

Suggested progression

  • 2.1 – Build the user index and use it to implement get_todos_by_user.
  • 2.2 – Build the completion index and use it to get all completed or pending todos.
  • 2.3 – Compare your code clarity with and without indices.

Hints

  • Think of indices as “precomputed groupings” you can reuse instead of scanning the list every time.
  • Even if performance differences are small here, the pattern matters for larger datasets.

Task 3 · sets and uniqueness

Use sets to reason about unique users and relationships between completion and pending work.

Requirements

  • Create scripts/sets_playground.py.
  • Load todos.json (either directly or via load_todos).
  • Perform operations such as:
    • Compute the set of all userId values.
    • Compute the set of users who have at least one pending todo.
    • Compute the set of users whose todos are all completed.
    • Use set operations (union, intersection, difference) to compare these sets.

Suggested progression

  • 3.1 – Start with a simple set of all userId values.
  • 3.2 – Derive users_with_pending and users_with_completed_only.
  • 3.3 – Use set difference and intersection to answer “Who still has work to do?”

Hints

  • Sets are ideal when you care about membership and uniqueness rather than order.
  • Relate this to ML scenarios where you track unique users or labels, even if we are not doing ML yet.
