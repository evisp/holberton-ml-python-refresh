Project 1

Python essentials – utility scripts on tabular data

In this first project you get comfortable running Python scripts from the command line, working with simple tabular files, and writing small, clean functions. No heavy data structures yet— just foundations you will reuse in every later project.

🐍 Python scripts 📁 File I/O ⌨️ Command-line ⚠️ Error handling
Focus: functions, modules, file reading Data: small pipe-delimited sample file Goal: confidence before JSON & pandas

Key concepts

  • Writing and calling functions from scripts.
  • Using if __name__ == "__main__": as an entry point.
  • Reading text files safely with with open(...).
  • Using command-line arguments (sys.argv or argparse).
  • Handling common errors (missing files, bad numbers).

Study first (15–30 minutes)

  • Rusty or new to Python? Work through the Week 1 Python foundations tutorial first — it covers everything below from the ground up.
  • Python docs: tutorial chapters on functions and modules.
  • Python docs: file I/O and the with statement.
  • Quick overview of sys.argv and argparse for arguments.

Skim these before you start coding. The tasks assume you know the basics, but they reinforce them through practice.

Sample data – pipe-delimited orders file

All tasks in this project use a small, pipe-separated text file representing orders. The exact values do not matter, but the structure does.

File structure

You will work with a file called project01/data/sample_orders.txt containing one header row and multiple data rows. Columns are separated by the pipe character |.

Expected columns:

order_id|customer|product|quantity|price
123|Alice|Notebook|2|4.50
124|Bob|Pen|10|1.20
125|Alice|Backpack|1|29.99
...

Each data row has:

  • order_id: integer.
  • customer: short name.
  • product: short name.
  • quantity: integer.
  • price: decimal number (float).

How to create the file

You have two options:

  • Option 1 – download a prepared file: use any small pipe-delimited sample file you trust, and save it as project01/data/sample_orders.txt.
  • Option 2 – generate with an AI tool: ask your AI assistant something like:
    “Generate a small pipe-delimited text file with columns order_id, customer, product, quantity, price. Include a header row and about 20–30 rows of realistic but fake data. Use | as the separator.”
    Then copy the output into project01/data/sample_orders.txt.

Once you have the file, you are ready to start the tasks.

Tasks

Start with simple scripts, then layer arguments and error handling. Use the expandable cards as checkpoints.

Task 0 · warm-up – print file summary

Read a pipe-delimited file and print basic information: header, line count, and a few sample rows.

Requirements

  • Create scripts/print_file_info.py inside project01/.
  • The script should accept a file path as a command-line argument (for example using sys.argv).
  • Use project01/data/sample_orders.txt as your default test file.
  • Print:
    • The total number of lines in the file.
    • The header row.
    • The first 3 data rows.
  • If the file does not exist, print a clear error message and exit with a non-zero code.

Hints

  • Start with a hardcoded path to data/sample_orders.txt, then refactor to use arguments.
  • Use a with open(path) block to read the file safely.
  • You can use enumerate when iterating over lines to detect header vs data rows.

Task 1 · basic stats – totals from tabular data

Compute simple statistics (counts, totals) by looping over rows and doing basic arithmetic.

Requirements

  • Create scripts/order_stats.py.
  • Read data/sample_orders.txt line by line.
  • Skip the header row.
  • For each data row:
    • Split the line on "|" into columns.
    • Parse quantity and price as numbers.
  • Compute and print:
    • Total number of orders.
    • Total quantity ordered (sum of quantity).
    • Total revenue (sum of quantity * price).

Hints

  • You can keep counters (integers and floats) and update them inside your loop.
  • Use a small helper function (for example parse_order_line(line)) to keep your code organized.
  • Start with a few rows to test your logic before trusting the totals.

Task 2 · command-line options & error handling

Add arguments and defensive checks so your script behaves well when inputs are missing or invalid.

Requirements

  • Extend order_stats.py or create order_stats_cli.py that wraps your stats logic.
  • Use argparse (or sys.argv + manual parsing) to add options such as:
    • --file PATH – path to the input file (default data/sample_orders.txt).
    • --limit N – maximum number of data rows to process (optional).
  • Add basic error handling:
    • If the file cannot be opened, print a clear message and exit with a non-zero code.
    • If a row has invalid numbers for quantity or price, handle it gracefully (for example, skip the row and count it as “invalid”).
  • Print a short summary at the end, including how many rows were processed and how many were invalid.

Hints

  • Wrap file opening and numeric conversion in try/except blocks.
  • Use default values for arguments so you can run the script without always specifying options.
  • Keep your core calculation logic separate from the argument parsing so you can reuse it later.

Task 3 · toolbox entry point

Expose your utilities through a single command-line “toolbox” script that routes to the functionality you built.

Requirements

  • Create toolbox.py in the root of project01/.
  • The toolbox should support simple subcommands, for example:
    • python toolbox.py info data/sample_orders.txt – calls your file info script.
    • python toolbox.py stats --file data/sample_orders.txt – calls your stats logic.
  • Reuse the functions you wrote in the previous tasks instead of duplicating logic.
  • Use a clear main() function and if __name__ == "__main__": guard.

Hints

  • You can implement subcommands using argparse subparsers or simple sys.argv[1] checks.
  • Keep the routing logic in toolbox.py thin: import and call functions from scripts/.

Stretch · structured rows

Refactor row parsing into small data structures to prepare for later JSON projects.

Optional

Ideas

  • Implement a helper parse_order_line(line) that returns a dictionary with keys order_id, customer, product, quantity, price.
  • Use this dictionary in your stats functions instead of working with bare lists of strings.
  • Think about how this pattern relates to JSON records in Project 2.
