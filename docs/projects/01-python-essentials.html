Project 1

Python essentials – utility scripts

In this project you build a small toolbox of command-line scripts that read local files, compute simple statistics, and prepare you for more data-heavy projects.

Learning goals

  • Refresh Python basics: functions, loops, conditionals, modules
  • Practice reading and writing files with clear error handling
  • Use command-line arguments to make scripts reusable
  • Organize a small project inside a larger repository structure

Project context

All projects in this refresh path live inside a single repository that you own. Each project uses its own folder (for example project01/, project02/), so you can grow a coherent codebase over time.

For this project, you will work with a public-domain essay from Project Gutenberg: Short Stories and Essays (from Literature and Life) by William Dean Howells (Project Gutenberg ID 3379).

Download the sample text

You will use one shared text file for all tasks in this project. Everyone works from the same source.

Public-domain essay from Project Gutenberg

Download the plain text UTF-8 version of Short Stories and Essays (from Literature and Life) by William Dean Howells from Project Gutenberg:

https://www.gutenberg.org/ebooks/3379.txt.utf-8

Save this file in your own repository as: 

project01/data/sample.txt

Project Gutenberg texts include a header and footer describing the project and license. You can keep them as part of the text; they will simply be included in your counts and statistics.

Your repository layout

Keep one repository for all projects and a separate folder per project. For this project, everything lives in project01/.

All core tasks (0, 1, and 2) use project01/data/sample.txt as their default input file. Task 3 can reuse the same file or another text file you choose.

Task 0 · warm-up – preview a file

Make sure your environment is ready and get comfortable reading files from the command line.

Requirements

  • Create a script scripts/file_preview.py inside project01/.
  • The script takes a file path as a required argument.
  • Use project01/data/sample.txt as your default test file.
  • Print the first N lines (default 10) of the file to the terminal.
  • If the file does not exist, print a clear error message and exit with a non-zero code.

Hints

  • Use sys.argv or argparse to handle command-line arguments.
  • Use a with open(path) block to read the file safely.
  • Start with a hardcoded path to data/sample.txt, then refactor to use arguments.

Task 1 · file statistics

Build a script that computes simple statistics about a text file: lines, characters, and non-empty lines.

Requirements

  • Create scripts/file_stats.py.
  • Implement a function compute_file_stats(path) that returns a dictionary of stats.
  • The script should:
    • Take a file path from the command line (start with data/sample.txt).
    • Print the number of lines, characters, and non-empty lines.
  • Handle invalid paths and unreadable files gracefully.

Suggested progression

  • 1.1 – Start with a hardcoded path to data/sample.txt and print the stats.
  • 1.2 – Add command-line arguments so you can pass any path.
  • 1.3 – Wrap file access in try/except and return a non-zero exit code on error.

Task 2 · word count and frequencies

Count how often each word appears in sample.txt and explore different ways to implement it.

Requirements

  • Create scripts/word_count.py.
  • Implement a function count_words(text) that returns a dictionary mapping words to counts.
  • The script should:
    • Read the contents of a text file passed as an argument (start with data/sample.txt).
    • Normalize text (for example, lowercase and strip basic punctuation).
    • Print the top N words (default 10) and their counts.
  • Add an optional argument --top N to control how many results to show.

Suggested progression

  • 2.1 – Implement count_words with a plain dictionary and loops.
  • 2.2 – Rewrite it using collections.Counter and compare both versions.
  • 2.3 – Add a --min-length argument to ignore very short words.

Hints

  • Keep your counting logic separate from printing; this makes testing easier.
  • Use the same sample.txt so you can compare results with other students.

Task 3 · filter lines by pattern

Build a script that reads lines from a file, keeps only the ones that match a pattern, and writes them to a new file.

Requirements

  • Create scripts/filter_lines.py.
  • The script should accept:
    • --input FILE – path to the input file (start with data/sample.txt).
    • --output FILE – path to the output file (for example data/filtered.txt).
    • --contains STRING – keep only lines that contain this substring.
  • Read the input file line by line and write only matching lines to the output file.
  • At the end, print a short summary: “Kept X / Y lines”.

Suggested progression

  • 3.1 – Implement filtering by substring with required arguments.
  • 3.2 – Add a --ignore-case flag so that matching is case-insensitive.
  • 3.3 – Decide what to do if the output file already exists (warn, prompt, or overwrite).

Hints

  • Reuse data/sample.txt to avoid downloading a new file.
  • Track total lines and kept lines to compute your summary.

Task 4 · toolbox entry point

Expose your scripts through a single command-line “toolbox” that routes to the functionality you built.

Requirements

  • Create toolbox.py in the root of project01/.
  • The toolbox should support subcommands, for example:
    • python toolbox.py stats data/sample.txt
    • python toolbox.py preview data/sample.txt
    • python toolbox.py wc data/sample.txt --top 5
  • Reuse the functions you wrote in the previous tasks instead of duplicating logic.
  • Use a clear main() function and if __name__ == "__main__": guard.

Suggested progression

  • 4.1 – Implement stats and preview subcommands.
  • 4.2 – Add a wc subcommand that calls your word count logic.
  • 4.3 – Make sure python toolbox.py -h prints helpful usage text.

Hints

  • argparse supports subparsers for subcommands; explore this pattern.
  • Keep the routing logic in toolbox.py thin: import and call functions from scripts/.

Stretch goals (optional)

These are optional challenges for when you want to push a bit further or prepare for later projects.

Optional extensions

  • Add a --json flag to file_stats.py to output stats as JSON. This will prepare you for later projects that chain tools together.
  • Create a tests/ folder inside project01/ and write a few simple tests (for example with pytest) for count_words and compute_file_stats.
  • Add basic logging to filter_lines.py to log the start, end, and number of lines processed.
