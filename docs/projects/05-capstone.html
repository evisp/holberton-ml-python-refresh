Project 5

Capstone – user activity report from JSON data

In this capstone project you combine multiple JSONPlaceholder datasets (users, posts, comments, todos) to build a small user activity report. You will load data, link records together, compute metrics, and generate a simple report and a few plots.

Learning goals

  • Work with multiple related JSON files in a single project.
  • Use Python data structures (lists, dicts, sets) to create user-centric views of the data.
  • Compute simple user-level metrics from raw records.
  • Generate a text-based report and basic visualizations.

Project context

This capstone builds on all previous projects: file handling, data structures, simple pipelines, and basic exploratory analysis. You will reuse patterns and ideas you have already practiced.

The data comes from JSONPlaceholder, a public fake REST API for testing and prototyping. You will download four resources once, save them locally, and work entirely from files.

Download the JSONPlaceholder data

You will work with users, posts, comments, and todos. Each resource is stored as a local JSON file.

Data sources

JSONPlaceholder provides several related resources. In this project you will use:

  • /users – user profiles
  • /posts – blog posts
  • /comments – comments on posts
  • /todos – todo items

API endpoints:

https://jsonplaceholder.typicode.com/users
https://jsonplaceholder.typicode.com/posts
https://jsonplaceholder.typicode.com/comments
https://jsonplaceholder.typicode.com/todos

Download with curl

From the root of your repository, run:

mkdir -p project05/data

curl https://jsonplaceholder.typicode.com/users    -o project05/data/users.json
curl https://jsonplaceholder.typicode.com/posts    -o project05/data/posts.json
curl https://jsonplaceholder.typicode.com/comments -o project05/data/comments.json
curl https://jsonplaceholder.typicode.com/todos    -o project05/data/todos.json

After this step, you should have four JSON files in project05/data/.

Task 0 · load all resources

Create a small module that knows how to load all four JSON files into memory.

Requirements

  • Create scripts/load_data.py inside project05/.
  • Implement functions such as:
    • load_users(path)
    • load_posts(path)
    • load_comments(path)
    • load_todos(path)
  • Each function should:
    • Open the JSON file.
    • Parse it with the json module.
    • Return a list of dictionaries.
  • Optionally add a convenience function load_all(data_dir) that returns a dictionary containing all four lists.

Hints

  • Reuse patterns from Projects 2 and 3 for loading JSON.
  • Keep load_data.py focused on I/O so other modules can assume they receive Python objects.

Task 1 · build user-centric data structures

Create in-memory mappings from users to their posts, comments, and todos.

Requirements

  • Create scripts/user_metrics.py.
  • In this script:
    • Import your loading functions from load_data.py.
    • Build indices such as:
      • user_posts: dictionary mapping userId to a list of posts.
      • user_todos: dictionary mapping userId to a list of todos.
      • user_comments: dictionary mapping userId to comments made on that user’s posts.
  • Use these indices to compute, for each user:
    • num_posts
    • num_comments_on_posts (total comments on their posts)
    • num_todos
    • completion_rate (completed todos / total todos)

Hints

  • Start by building a mapping from postId to owner userId, then use it to assign comments to the correct user.
  • Focus on clear loops and dictionary updates; your goal is to practice data structure design more than performance optimization.

Task 2 · compute user metrics and summary table

Combine your indices into a small table of user-level metrics.

Requirements

  • Extend user_metrics.py with a function such as compute_user_metrics(users, posts, comments, todos).
  • This function should return a list of dictionaries, each representing one user, with fields such as:
    • user_id
    • user_name
    • num_posts
    • num_comments_on_posts
    • num_todos
    • completion_rate
  • Keep this implementation in pure Python (lists and dictionaries). Optionally, you may convert the result to a pandas DataFrame later for analysis or plotting.

Hints

  • Use the indices you built earlier to avoid scanning the entire dataset repeatedly.
  • Think of this summary as a mini “user activity table” that you can reuse in the report and plots.

Task 3 · generate a simple user activity report

Use your metrics to build a text-based report and optionally a CSV file of user metrics.

Requirements

  • Create scripts/report.py.
  • In this script:
    • Load all data using load_data.py.
    • Compute user metrics using compute_user_metrics.
    • Print a summary to the terminal, including:
      • Overall average completion rate (across all users).
      • The user with the most posts.
      • The user with the most comments on their posts.
      • The user with the highest completion rate.
    • Optionally write a CSV file project05/data/user_metrics.csv containing one row per user with the metrics you computed.

Hints

  • If you use pandas, you can convert your list of dictionaries to a DataFrame and use methods like df.sort_values() to find top users.
  • Even without pandas, sorting a list of dictionaries by a key (using sorted and a key function) works well.

Task 4 · plots – visualize user metrics

Create simple visualizations for your user metrics and save them to image files.

Requirements

  • Create scripts/plots.py.
  • In this script:
    • Load or compute the user metrics table.
    • Use matplotlib or pandas plotting to create:
      • A bar chart of number of posts per user, saved as figures/user_activity_bar.png.
      • A bar chart of completion rate per user, saved as figures/completion_rate_bar.png.
  • Make sure the figures/ folder exists before saving plots.

Hints

  • Use plt.savefig("project05/figures/filename.png", dpi=150) to save your plots.
  • Label axes clearly (for example, “User” on the x-axis and “Number of posts” on the y-axis).

Stretch goals (optional)

Extra challenges if you want to deepen your understanding of data relationships and metrics.

Optional extensions

  • Define a simple “engagement score” for each user (for example, num_comments_on_posts / max(num_posts, 1)) and add it to your metrics.
  • Compute and print the top 3 users for each metric (posts, comments, completion rate, engagement).
  • Create a tiny CLI “dashboard” script (for example scripts/dashboard.py) that lets you choose which metric to display in a table or print to the terminal.

Reflection and notes

Connect this capstone project to how you think about data and future work.

Project notes

Create a file project05-notes.md inside project05/ and write short answers to these questions:

  • Which metric do you think best captures “user activity” in this dataset? Why?
  • How did building indices (user → posts → comments → todos) change how you think about data relationships?
  • If you swapped JSONPlaceholder for a real dataset, which parts of your capstone would you keep exactly the same?

These reflections help you see how small, structured projects can scale to more complex data work, including—but not limited to—machine learning.
